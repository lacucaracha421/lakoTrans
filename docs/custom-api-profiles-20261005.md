# 사용자 지정 API 세션과 OpenCode GO 빠른 설정

## 현재 사용 방법

이름이 있는 연결 프로필의 생성·선택·이름 변경·삭제 화면은 제거했다.
기존 **API 제공자 빠른 설정 → OpenCode GO**를 선택하고 본인의 API 키를 입력하면 된다.
주소, 모델, 세션 헤더, 응답 형식이 함께 설정된다.

| 설정             | 기본값                                       |
| ---------------- | -------------------------------------------- |
| Base URL         | `https://opencode.ai/zen/go/v1`              |
| 모델             | `deepseek-v4.1-flash`                        |
| 대화별 세션 헤더 | 켜짐, `x-opencode-session`                   |
| 추가 요청 JSON   | `{"response_format":{"type":"json_object"}}` |
| 기본 User-Agent  | `CarrotMangaTranslator/<실제 앱 버전>`       |

연결 시험 후 저장한다. 추가 요청 JSON의 JSON 모드는 유지해야 한다. 모델 자동 검색은
제공하지 않으며 모델 ID는 직접 수정할 수 있다. OpenCode 실행·ACP·MCP 기능은 포함하지
않는다. 앱은 OpenCode 인증 파일을 자동 탐색하거나 가져오지 않는다.

이전 버전의 `api.customProfiles` 데이터와 활성 사용자 지정 연결은 호환성을 위해
보존한다. 새 이름 프로필이나 Go 이름 프로필을 자동 생성하지 않는다. Go 빠른 설정은
기존 제공자별 저장·전환 계약을 사용하며, 암호화 키도 `opencode-go`에 독립 보관한다.
이전 `custom:<id>` 키를 자동 복사하지 않는다. 현재 PC의 활성 연결·OpenCode 설정과
로컬 개발환경은 변경하지 않았다.

## HTTP 400 재현과 수정

초기 합성 페이지 3장 시험에서는 일부 요청이 `{"model":"deepseek-v4.1-flash"}`만 담은
400을 반환했다. 실제 작품으로 확장한 초기 검사에서도 17개 이미지 요청 중 16개가
400이었다. 당시 요청은 앱이 강제한 `response_format.type=json_schema`였다.

세션 형식을 UUID로 바꾸면 일부 요청은 성공했지만 다른 작품에서 다시 실패했다.
이 실험은 채택하지 않았다. **같은 실패 세션·이미지·메시지·모델·User-Agent를 고정**한
추가 비교에서 JSON Schema는 400, JSON object와 형식 생략은 각각 200이었다.
세션 길이만으로 원인을 설명할 수 없고, 재현된 실패는 JSON Schema 호환성 문제다.

공통 구조화 요청 생성부가 사용자 추가 JSON의 명시적인 `json_object` 선택을 존중하도록
수정했다. Go 빠른 설정이 이 값을 채운다. 런타임에 공급자명·호스트명으로 오류를 우회하는
분기는 추가하지 않았다. [DeepSeek 공식 JSON 모드 문서](https://api-docs.deepseek.com/guides/json_mode/)가
명시한 응답 형식이다. 전체 페이지 이미지와 OCR, 고정 블록 ID·누락·중복 검증은 유지한다.
정보가 없는 400을 무조건 재시도하거나 다른 모델·주소로 전환하지 않는다.

마지막 연결 시험에서 별도의 400도 재현했다. JSON 모드를 요구하면서 시험 프롬프트에
JSON 안내가 없었던 것이 원인이었다. 같은 실패 세션을 고정한 비교에서 서버가
`Prompt must contain the word 'json'`이라고 응답했고, JSON 형식이 요구될 때의 간단한
응답 예시를 시험 프롬프트에 추가하자 200과 `{"message":"model test ok"}`를 받았다.
이미지 입력·30초 취소 기한·외부 API 1,024토큰/로컬 48토큰 예산은 유지했다.
증거는 `.tmp/go-json-probe-control.json`, `.tmp/go-json-probe.json`에 있다.

## 유지되는 저장·실행 계약

- 실행 옵션 생성 시 연결 값과 실행 난수를 고정한다. 페이지 수명 경계에서 실행 난수와
  페이지 식별자로 세션 ID를 만들고 검수·보정·재시도에 유지한다. 다른 페이지, 새 작업,
  연결 시험과 독립 문맥 요청은 별도 ID다. 전역 세션이나 영구 세션 저장은 없다.
- 이미지 다운로드 등 모델 요청 외 통신에는 세션 헤더를 붙이지 않는다. 사용자가 지정한
  User-Agent는 유지한다. 인증·전송 제어 이름 및 사용자 헤더와의 세션 이름 충돌은 거부한다.
- 인증·권한·사용량 한도·일시적 제한·이미지 미지원 오류를 구분한다. 명시적인 한도는
  중단하고, 일시적인 429는 기존 시도·취소 정책 안에서 Retry-After를 반영한다.
- 이미지 거부를 텍스트 전용 번역으로 낮추지 않는다. 명시적인 JSON Schema 거부의 제한된
  JSON 모드 재요청과 응답 검증도 유지한다.
- 백업은 세션 설정을 보존하고 기존 정책대로 인증 정보·사용자 헤더·추가 JSON은 제외한다.
  복원 후 키와 JSON 모드를 다시 확인해야 한다.

## 실제 작품 검증

검증용 Electron 프로세스 메모리에서만 기존 Go 자격 증명을 사용한다.
[Go 공식 연결 명세](https://opencode.ai/docs/go/)의 주소·모델·세션 헤더와 실제 앱 버전의
User-Agent를 사용한다. 자격 증명과 인증 헤더는 보고서에 기록하지 않는다.

기존 50작품·100페이지 표본에서 텍스트가 있는 페이지를 작품당 하나 선택한다.
원본 SHA-256을 대조하고 저장된 실제 OCR 블록과 페이지 이미지를 정상 앱의
`translateWorkflowPage` 경로로 번역한다. 새 OCR 추론이나 지우기·식자까지 실행한 검사는
아니다. 결과는 `.tmp/go-real-pages/json50/`의 페이지별 `completed.json`과 앱 artifact로
저장하고 원본 보관함에는 쓰지 않는다.

로컬 재현 자료:

- `.tmp/go-real-pages/baseline20/report.json`: 수정 전 실제 작품 오류
- `.tmp/go-real-pages/uuid50/report.json`: UUID로도 오류가 남는 반증
- `.tmp/go-failed-session-format.json`: 실패 세션 고정 응답 형식 비교
- `.tmp/go-real-pages/json50/report.json`: 수정 후 실제 작품 검사

최종 결과는 **50작품·50페이지 성공, HTTP 요청 51회 모두 200, 400 재발 0회**다.
한 페이지의 기존 블록 보정 1회도 동일 세션과 전체 이미지를 유지했다. 원본 SHA-256,
페이지 간 세션 격리, 모든 요청의 JSON 모드·실제 User-Agent·이미지 첨부를 대조했다.
모델 결과의 고정 슬롯은 총 254개이며 누락·중복 없이 검증됐다. 최종 대사 블록 253개가
저장됐다. 차이 1개는 W22-P2의 `・・・・・・` → `……`로, 모델이 정상 반환한 뒤 기존
`overlayItemReferences.isFragmentNoise`의 기호 전용 필터가 제외한 것이다. 이번 수정에서
필터를 변경하지 않았으며 모든 블록이 무조건 저장됐다고 해석하면 안 된다.

원본 표본의 페이지 모음 이미지를 직접 열어 말풍선·독백·짧은 대사·컬러 표지·밀집 페이지 구성을
확인했다. 이 검사는 HTTP 호환성과 블록 대응 검증이며, 50작품 전체 번역의 인명·문맥·
자연스러움에 대한 완전한 수동 품질 인증은 아니다. 결과 감사는 같은 폴더의
`validation.json`에 기록했다.

## 회귀와 화면 검증

로컬 HTTP 서버에서 불투명한 Schema 400을 반환하는 API를 재현했다. 명시적 JSON 모드가
첫 요청부터 전달되고, 누락 블록 보정에서도 같은 세션과 이미지를 유지하는지 검사한다.
기존 인증·한도·취소·병렬 세션 격리 회귀도 실행한다. UI 테스트는 빠른 설정 전환,
기본 JSON 값, 세션 입력 검증, 실제 앱 버전 표시, 늦게 도착한 이전 연결 시험 무시를 검사한다.

실제 설정 컨트롤러와 프로덕션 화면을 `qa:ui`로 1440×900, 720×900에서 캡처하고
잘림·겹침·새 가로 오버플로가 없음을 직접 확인했다. 임시 QA 엔트리는 제거했다.
캡처는 `C:/tmp/go-preset-wide.png`, `C:/tmp/go-preset-narrow.png`에 보존한다.

삭제한 프로필 컴포넌트의 세션 부분을 `ApiSessionFields.tsx`로 유지하면서 기존 커버리지
하한을 그대로 옮겼다. 하한은 낮추지 않았다. 해당 경로 변경을 반영한 도입 파일 증거 SHA-256은
`7e0f83700cfa1d2c264efbb3bd5b1cd0794927679d2ed1d988ba1893012e46e7`이다.

Node 26.10.0에서 `npm run check`의 실제 엔트리 `node scripts/check.cjs`를 통과했다.
연결 시험 수정까지 포함해 테스트 10,213개 통과·9개 건너뜀, 타입·린트·형식·아키텍처·커버리지 하한 검사와
프로덕션 빌드, artwork pixel parity, 이미지 프로토콜 및 renderer/preload bundle 검사가
성공했다. 최종 전체 기록은 `.tmp/go-json-probe-final-check.log`, 단계별 기록은 `.tmp/check-logs/`,
기계 판독 결과는 `.tmp/check-results/vitest.json`이다.
