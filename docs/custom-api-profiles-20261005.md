# 사용자 지정 API 프로필과 대화 세션

사용자 지정 API에 이름이 있는 다중 연결을 추가했다. 제공자별 기존 설정과 활성 설정
투영을 유지하며, 사용자 지정 연결의 주소·모델·키·헤더·추가 JSON·생성 한도·재시도·세션
설정을 각각 보관한다. OpenCode를 실행하거나 ACP/MCP를 연결하는 기능은 아니다.

## 사용 방법

1. 설정 → 번역 → API → 직접 설정에서 연결 프로필을 선택한다.
2. 기본으로 제공하는 **OpenCode Go**를 선택하고 본인의 API 키를 입력한다.
   주소는 `https://opencode.ai/zen/go/v1`, 모델은 `deepseek-v4.1-flash`다.
3. 고급 요청 설정의 대화별 세션 헤더가 켜져 있고 이름이 `x-opencode-session`인지
   확인한다. 일반적인 다른 서비스에서는 기본값인 꺼짐을 유지할 수 있다.
4. 연결 시험 후 저장한다. 다른 연결은 프로필 추가로 만들고, 이름을 직접 수정한다.
   마지막 남은 프로필은 삭제 버튼이 비활성화된다.

OpenCode Go는 일반 사용자 지정 프로필의 초기 데이터다. 별도 제공자·로고·호환 분기는
없으며, 지우면 다시 생성하지 않는다. 프로필을 새로 만들 때 다른 연결의 키는 복사하지
않는다. 앱은 OpenCode 인증 파일을 자동 탐색하거나 가져오지 않는다.

## 저장과 실행 계약

- `api.customProfiles`와 `api.activeCustomProfileId`가 이름과 선택을 보관한다.
  기존 단일 사용자 지정 설정은 최초 저장 때 `default` 프로필로 이관된다.
- 비밀값은 기존 OS 암호화 보관함의 `apiProfiles` 안에서 `custom:<id>`로 분리한다.
  이전 단일 `custom` 별칭은 이관 후 제거한다. 삭제한 ID의 키를 보존하지 않으며,
  기존 키 유지 표시는 같은 ID의 자격 증명에만 적용된다.
- 생성 한도는 사용자 지정 프로필 안에도 보관하고 기존 활성 한도에 투영한다.
- 환경 백업은 프로필 ID·이름·세션 설정을 보존한다. 기존 정책대로 인증 정보와 사용자
  헤더·추가 JSON은 내보내지 않으며, 복원 후에는 키를 다시 입력해야 한다.
- 실행 옵션을 만들 때 연결 값과 실행용 난수를 고정한다. 페이지 수명 경계에서
  실행 난수와 페이지 식별자로 불투명한 세션 ID를 만들고 모든 검수·보정·재시도에
  유지한다. 새 작업과 다른 페이지는 다른 ID다. 연결 시험과 독립 문맥 요청은 별도 ID다.
- 세션 난수와 ID는 설정이나 번역 결과 artifact에 영구 저장하지 않는다.
  이미지 다운로드 등 모델 요청 외의 통신에는 세션 헤더를 붙이지 않는다.
- 기본 식별값은 `CarrotMangaTranslator/<실행 앱 버전>`이다. 사용자 지정 User-Agent가
  있으면 대소문자와 관계없이 유지한다. 인증·전송 제어 이름 및 사용자 헤더와의
  세션 이름 충돌을 거부한다.
- 명시적인 사용량·잔액 한도와 권한 거부는 키 순환을 중단한다. 일시적인 429는 기존
  시도 횟수와 취소 범위에서 `Retry-After` 초 또는 HTTP 날짜를 존중한다. 다른 프로필,
  모델, 과금 주소로 전환하지 않는다.
- 이미지 거부 시 텍스트 전용으로 낮추지 않는다. 고정 블록 ID, 누락·중복 검증과 기존의
  제한된 JSON Schema → JSON 모드 재요청을 그대로 사용한다.

## 실제 연결 검증 — 2026-10-05

[Go 공식 연결 명세](https://opencode.ai/docs/go/)의 주소·모델·세션 헤더와 실제
`CarrotMangaTranslator/3.1.1` 식별값을 사용했다. 기존 Go 자격 증명은 검증용 Node
프로세스 메모리에서만 읽었다. 현재 활성 앱 연결 및 OpenCode 설정은 바꾸지 않았다.

기존 `testModelReply` 연결 시험은 처음에는 48토큰 제한으로 잘렸다. 외부 API 시험의
예산을 1,024토큰으로 조정한 뒤 이미지 확인 응답을 받았다. 로컬 모델 시험의 기존
48토큰 예산과 시험 시간 제한은 유지했다.

일본어 말풍선 2개씩 있는 합성 페이지 3장을 기존 `requestTranslation`의 Hayai 보관
블록 경로로 전송했다. 전체 페이지 PNG와 고정 OCR 입력을 함께 사용했으며, OCR 모델
자체를 다시 실행한 시험은 아니다. 기존 고정 블록 응답 검증을 통과한 결과를
`saveArtifacts`로 저장했다. 세 페이지 모두 2개 블록이 원문 ID에 맞게 저장됐다.

| 페이지 | 원문 예                  | 저장된 번역 예           |
| ------ | ------------------------ | ------------------------ |
| 1      | おはよう、ユキ！         | 좋은 아침, 유키!         |
| 2      | この鍵はどこにあった？   | 이 열쇠는 어디에 있었어? |
| 3      | もちろん。一緒に帰ろう。 | 물론이지. 같이 돌아가자. |

연속 호출 중 페이지 2와 3의 최초 시도는 HTTP 400을 반환했다. 확인한 오류 본문은
`{"model":"deepseek-v4.1-flash"}`로 이유를 설명하지 않았다. 각각 별도 실행에서 같은
설정으로 성공했다. 이 응답을 회피하는 자동 재시도나 서비스 전용 우회는 추가하지
않았다. 따라서 실제 연결과 세 페이지 성공은 확인했지만 연속 호출의 안정성까지
보장하지 않는다. 이 시험 결과는 서비스의 모든 이용 목적을 승인한다는 의미도 아니다.

로컬 증거: `.tmp/custom-api-live/report.json`, `report-remaining.json`,
`report-final-page.json`, `result-1/result.json`부터 `result-3/result.json`까지.
자격 증명·인증 헤더는 보고서에 포함하지 않았다. 실제 서비스에서는 이 세 합성
페이지 외의 작품이나 대량 오류 시험을 보내지 않았다.

## 회귀 및 화면 검증

- 설정: 최초 이관, 이전 보관함 키, ID별 마스킹·복원, 실제 암호화 파일 저장 후 재읽기,
  프로필 전환·삭제, 독립 생성 한도, 잘못된 비활성 프로필 보존 검증. 실제 백업 ZIP을
  다른 임시 데이터 경로에 복원해 세션 설정 보존과 인증 정보 제외도 검사했다.
- 통신: 로컬 HTTP 서버에서 페이지/병렬/시험 ID 분리, JSON 모드 재요청·키 재시도·누락
  블록 보정·페이지 재시도의 ID 유지, 전체 이미지 유지, 헤더 충돌, 인증/한도/권한 오류,
  Retry-After 대기 및 취소를 검사한다.
- UI: 실제 폼과 프로덕션 컴포넌트로 생성·이름 변경·전환·삭제, 세션 오류 안내,
  실제 버전 표시와 이전 프로필의 늦은 시험 결과 무시를 검사한다.
- `qa:ui`에서 실제 설정 컨트롤러와 화면을 1440×900 및 720×900으로 렌더링했다.
  모달 내부 스크롤만 사용하며 새 입력의 잘림·겹침은 없었다. 캡처는
  `C:/tmp/custom-api-wide-2.png`, `custom-api-narrow-1.png`,
  `custom-api-session-wide.png`, `custom-api-session-narrow.png`에 보관한다.
  QA 브리지는 앱 버전을 제공하지 않으므로 해당 캡처의 기본 식별값은 로딩 상태다.
  버전 표시의 완료 상태는 실제 버전 응답을 사용하는 컴포넌트 테스트에서 검증한다.

설정 프로필 정규화 코드는 `appSettingsApiProfile.ts`로 분리했으며 기존 설정 회귀를
그대로 실행한다. 공용 기본값·저장 이관·페이지 수명 모듈의 직접 의존 증가 3건만
실측 아키텍처 예산에 기록했다. 기존 커버리지 하한은 낮추지 않는다. 새로 변경한
기존 파일 2개의 하한은 원래 Node 22 증거에서 가져오고, 새 모듈 8개의 최초 Windows
측정값을 기존 도입 파일 목록에 추가한다.

최종 `npm run check`는 Node 26.10.0에서 통과했다. 1,318개 테스트 파일 중 1,317개가
통과하고 기존 1개 파일은 건너뛰었으며, 테스트 10,211개 통과·9개 건너뜀이 기록됐다.
타입 검사, 린트, 형식, 아키텍처, 커버리지 하한, 프로덕션 빌드, 페이지 artwork pixel
parity, 이미지 프로토콜 smoke와 renderer/preload bundle 검사를 모두 통과했다.
새 도입 파일 측정 artifact SHA-256은
`710ee036cbe46619038c0d7ec966efc633a2127cea95a8998d2be88954f22380`이다.
전체 실행 기록은 `.tmp/custom-api-full-check-final.log`, 단계별 기록은
