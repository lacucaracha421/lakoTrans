# 정밀 MCP 번역과 생성 한글 보정 — 2026-10-08

## 현재 상태

기본 번역 가이드와 composite 완료 정책을 `complete-translation-v2`로 연결했다. 실제 렌더 계측, 문맥 안의 폰트 견본, 작품 팔레트, 실패 생성 후보 보존, 획 보정·부분 이동, 보정된 픽셀의 독립 재판독·자형 검사를 구현했다. OCR이 문구를 맞혀도 자모의 모양·상대 배치가 잘못되거나 판단이 불확실하면 정밀 완료를 승인하지 않는다. 기존 수동 편집과 명시적인 v1 정책은 유지한다.

**사용자 편집본보다 우수하다는 품질 목표는 통과하지 못했다.** 자동 검사와 네이티브 렌더 시험은 작품 품질 평가를 대체하지 않는다. 고정 비교 40페이지의 실제 실행과 세 비교군의 블라인드 평가를 모두 마쳤고, 악화 사례와 완료되지 않은 검수도 남겼다.

최신 기능의 실제 GPT-6 Astra 시험에서는 잘못 생성된 `쾅`·`욱`을 공개 MCP로 직접 보정한 뒤 두 자형이 통과했다. 별도 전체 7페이지도 **“이 화 번역해줘”라는 단문 요청으로 원본 열람·현재 revision의 정밀 검수·화 전체 완료 조회가 7/7**이었다. `npm run check` final20은 27개 gate, 테스트 10,450개가 통과했다. 이 결과와 이전 frozen producer의 40페이지 품질 비교를 섞지 않는다. [일반 사용법](mcp-user-guide.md#기본-번역과-완료-기준)과 아래 실행별 한계·기록을 함께 참고한다.

## 고정 40페이지의 최종 결과

두 실제 생산자는 각각 20개 화 묶음·40페이지를 끝냈고, 사용자 편집본을 포함한 출처 비공개 비교도 40/40으로 종료됐다. 아래 우열은 GPT-6 Astra의 평가이며 사람의 정답 판정이 아니다. 같은 원본에서 나온 한국어 비교본 세 종류는 모두 높이 1000px로 제공했고, 일본어 원본은 판독을 위해 원래 해상도로 제공했다. AI의 원화 손상 주장 중 두 영역 묶음은 픽셀 대조로 반증해 별도 주석으로 남겼다. 원래 점수·이미지·판정은 바꾸지 않았다.

정밀 검수 통과 35페이지 중 10페이지는 폰트 대체를 포함한다. 「쿠소게」 5화 6·23페이지, 「잊힌 영애」 4.3화 2페이지는 검수가 held로 남았다. 「발효 영애」 2화 7·12페이지는 생성형 배경 작업을 중단한 뒤 큰 효과음의 문자 생성 시도 없이 폰트로 대체했고, 필수 근거가 부족한 blocked 보고서로 끝났다. PNG가 있거나 모델이 자연어로 완료했다고 말해도 이 5페이지를 정밀 완료로 세지 않았다.

작품별 보류 평가에서는 네 작품이 각 3페이지 모두 종합 우세였고, 「발효 영애」는 1페이지 우세·2페이지 열세였다. 항목별 낮은 점수는 보류 평가 13페이지, 일반화 5페이지에 남았다. 따라서 다섯 작품 모두에서 최소 2페이지 우세·나머지 동등 이상이고 악화가 없어야 한다는 엄격한 기준은 **5작품 모두 미통과**다. 집계 상태는 `formal-completion-target-not-met`이며 품질 기준도 별도로 통과하지 못했다.

이는 실행 전에 고정한 버전의 결과다. 뒤에 추가한 전체 화 완료 조회, 자형 version 2와 부분 이동의 효과를 이 40페이지 점수로 입증하지 않는다. 최신 경로의 기능 근거는 별도의 7페이지 전체 화 시험과 두 자모 자율 보정 시험이며, 이들의 통과도 사용자 편집본 이상의 미적 품질을 보장하지 않는다. 후속 품질 개선을 평가하려면 이 보류 사례를 다시 보류 데이터라고 부르지 않고 새로운 비교 페이지를 정해야 한다.

원자료는 `.tmp/mcp-quality-v2-evaluation/evaluation-report.json`, 비교 화면은 같은 폴더의 `quality-review.html`이다. 1페이지의 중국어 평가문에는 SHA로 원문에 연결한 한국어 번역을 별도로 추가했다. 원문과 반증은 화면에서 함께 확인할 수 있다. 기준 작품 생산자가 일반화 예약에 도달해 종료한 것은 중복 실행 방지이며 모델 시험 실패가 아니다. 일반화 4개 화의 게시가 끝난 후 기존 실행기를 재개해 이미 완료된 20개 묶음을 건너뛰고 `benchmark-complete.json`을 기록했다. 모델을 다시 호출하거나 결과를 골라 교체하지 않았다.

최종 보존·무결성 검증은 2026-10-08 14:53 UTC에 통과했다. 원본·기존 출력 68/68, 사용자 저장 페이지 40/40이 고정 manifest와 동일하다. 최초 코드 inventory와 기준/분리 실행의 네 runtime을 대조했고, 일반화 8개 게시 묶음의 원본·복사본 SHA와 40개 블라인드 평가에 제공한 각 4장 이미지의 SHA도 모두 일치했다. `final-evaluation-integrity.json`, `source-preservation.json`, `user-state-preservation.json`에 기록했다. 코드·시험 파일은 final20 종료 이후 수정되지 않았으며 이후 변경은 문서와 격리 평가 도구·결과 화면이다. 커밋·앱 릴리스는 만들지 않았다.

## 초기 연결·개발 시험

초기에는 실제 GPT-6 Astra에 추가 품질 지시 없이 `이 화 번역해줘`를 실행했다. 격리된 개발용 1페이지 발췌이며 전체 화 시험이 아니다. 처음 두 번 중 두 번째 실행은 원본 검사, 대사 8곳·효과음 1곳 번역, 폰트 견본 조회와 작품 팔레트 미리보기까지 실행했다. `carrot_apply_work_typography`, `carrot_prepare_composite`, `carrot_update_page_blocks`는 `MCP tool call requires approval, but approval policy is never`로 거부됐다. 이 두 실행은 완료 성공으로 세지 않는다.

이후 사용자가 격리 평가본의 MCP 쓰기를 명시적으로 승인했다. 세 번째 실행은 별도 시험 호스트에서 `on-request`로 승인 요청을 받고, 해당 격리 서버의 번역·팔레트·이미지 편집 요청에만 승인 응답을 전달했다. production transport, MCP scopes와 destructive annotation은 변경하지 않았다. `live-development-03`은 대사 8곳·효과음 1곳을 처리하고 `complete-translation-v2`, `mode=detailed`로 실제 완료됐다. 보존된 composite 기록의 status=completed, 최종 렌더·원본·견본·팔레트 근거까지 확인했다. 모델의 자연어 완료 발언만으로 성공 판정하지 않았다.

동일한 원본·모델·추론 설정으로 변경 전 HEAD의 기본 MCP도 `live-baseline-01`에서 완료됐다. 세 비교군을 높이 1000px로 네이티브 렌더하고, 원본과 제작자 표시 없는 A/B/C 이미지를 독립 Astra에 전달한 개발용 블라인드 비교를 완료했다. 이 1페이지에서 나온 평가를 보류 15페이지의 결과나 전체 화 검증으로 확장하지 않는다.

`live-development-ferment-01`에서는 큰 효과음 4곳을 실제 생성했다. 한글 판독은 맞았지만 말줄임표 코드 표현 때문에 2곳, foreground 배치 조건 때문에 1곳이 제외되어 최종적으로 생성 1곳·폰트 대체 3곳이 됐다. 첫 완료 제출은 생성/복원 이력을 분리하지 않아 서버가 거절했고, 대체 목록을 명시한 재제출은 `accepted-with-font-substitutions`로 완료됐다. 이 시험으로 발견한 불필요한 대체 원인을 수정하고, 같은 원본을 새 격리 데이터 폴더 `live-development-ferment-02`에서 같은 단문 요청으로 다시 시험했다. 두 번째 실행에서 발견한 큰 생성 자산의 복구 용량 결함과 수정 검증은 아래에 별도로 기록했다.

첫 시험의 미리보기 오류는 격리 하네스에 `out/renderer` 스타일을 복사하지 않은 원인이었다. 이를 수정한 두 번째 실행에서는 폰트 견본과 렌더가 성공했다. 실제 연결에서 이미지 편집의 `geometry.kind` 및 start/end 입력 오류가 반복되어 공개 도구 설명에 정확한 픽셀 좌표 예시를 추가했다. 최종 검수 도구의 설명도 v2 필수 근거를 명시하도록 맞췄다. 기존 입력·출력 계약은 유지한다. 모델이 실패 원인을 설명한 문장과 실제 도구 오류를 구분한다.

## 실제 출력과 가독성

`PageArtwork`가 사용한 배치 모델을 기존 `inspectLastLayout`으로 읽는다. 별도의 자동 맞춤 엔진이나 전역 최소 폰트 크기를 추가하지 않았다. 한글 잉크는 같은 폰트/스타일의 Canvas `actualBoundingBox*`를 사용하며 블록별 고유 글리프·스타일 최대 64개를 측정한다. Canvas가 없거나 한글을 측정할 수 없으면 측정값을 꾸며내지 않는다.

계측 좌표는 블록 변형 전 원본 이미지 픽셀이다. 독서 배율에는 `textScaleX/Y`와 미리보기 `pixelMapping`을 적용해야 한다. 원근·왜곡과 원화 침범은 최종 이미지에서 따로 판단한다. 렌더된 em 크기와 한글 잉크 크기를 구분한다.

overflow, 고립된 한글 음절, 문장부호만 남은 줄, 본문 대비 작은 크기, 큰 영역의 빈약한 문단, 세로쓰기 이유를 검수 경고로 돌려준다. 모든 글자가 동시에 작으면 상대 비교가 놓치므로 페이지 높이 1000px 기준 잉크 높이 10px 미만도 경고한다. 이것은 검수용 신호다. 크기를 자동으로 바꾸거나 작은 혼잣말을 금지하지 않으며, 의도적인 예외는 블록별 이유로 남긴다. 형태소·이름 분리와 원화 침범을 자동으로 완벽히 판정한다고 주장하지 않는다.

기존 C23, 폰트 매칭 모델, 학습 자산, 자동 맞춤 알고리즘은 변경하지 않았다. `docs/font-matching-v2-production-handoff.md` 및 10월 7일 크기 보정 기록의 데이터 권위도 유지한다. AI가 선택한 팔레트의 origin은 `connected-ai`, confidence는 0이며 사용자 잠금이나 human gold로 승격하지 않는다.

## 생성 실패와 보정

후보와 영수증은 해당 data root의 `.mcp-quality`에 기존 durable JSON writer·경로 검증·library lock을 사용해 저장한다. `.mcp-quality/sfx`에는 PNG를 포함한 후보와 영역별 생성 예산이 남는다. 생성 호출 전에 예산을 차감하므로 연결 중단 뒤 같은 호출을 새 무료 시도로 취급하지 않는다. 앱 시도는 서버가 누적하며, 외부 호스트 시도는 호스트가 신고하는 값이라는 한계가 있다.

실패 PNG는 재판독 호출 전에 보존한다. 판독 서버가 끊겨도 후보가 사라지지 않는다. 재시도는 수정된 지시가 필요하며 같은 지시를 그대로 반복하면 거부한다. 정책상 거절은 해당 영역에서 종료한다. 올바른 결과가 나오면 즉시 멈춘다.

보정 명령은 전체 generatedLettering 객체를 덮어쓰지 않는다. 기존 `paintStrokes`, `maskStrokes`, `outline`, occlusion과 좌표 변환을 사용한다. `asset`/`page` 좌표는 각각 명시한 공간의 normalized_1000이며, PNG 부분 교체의 `patch.rect`는 asset 픽셀이다. 회전·원근·왜곡의 역변환을 재사용한다. PNG·원문·확정 번역문·다른 블록을 보존하고 기존 변경 계획과 복구 계약을 따른다.

후보 보정의 2회 제한과 저장된 페이지의 수동 lettering 편집은 구분한다. 기존 수동 편집 도구 자체를 두 번 이상 사용할 수 없게 막지는 않는다. 정밀 완료는 어느 경로로 수정했든 현재 합성 픽셀을 다시 검증해야 한다. 후보의 이전 readback에는 composition fingerprint가 있으므로 보정 뒤 옛 판독을 새 검증으로 간주하지 않는다.

실제 생성 시험에서 같은 세 점을 독립 판독기가 `...`, 확정 문구는 `…`로 표현해 불필요한 실패가 발생했다. 생성 후보와 최종 합성 검증이 같은 비교 함수를 사용하며, NFC·공백 처리에 더해 `…`만 세 점으로 정규화한다. 원래 판독문은 그대로 보존한다. 점 개수 차이, 빠진 받침과 다른 문장부호는 여전히 실패한다. NFKC 전체 적용이나 문장부호 제거로 오자를 숨기지 않는다.

여러 후보가 같은 페이지 revision에서 만들어졌을 때 하나씩 적용하면 나머지 후보가 오래된 revision이 된다. 이를 해결하기 위해 같은 페이지의 `candidateIds`를 하나의 기존 batch로 채택한다. 한 후보라도 오래됐거나 같은 블록의 후보를 두 개 선택하면 전체 준비가 거부된다. revision 검사를 완화하지 않으며 적용·Undo·Redo는 기존 페이지 단위 변경 계약을 따른다. 배치 조건만 탈락한 정상 PNG도 새로 생성할 필요 없이 이 경로에서 제안된 위치를 확인하고 사용할 수 있다.

부분 글자 생성 패치는 기존 외부 PNG 업로드·검증·적용 경로를 이용한다. 실제 통합 시험에서 워커 응답을 작은 삽입 PNG 크기로 검사해 전체 자산 크기를 거절하던 문제를 수정했다. 패치 결과는 원본 자산 크기로 검사하며 패치 밖 픽셀과 기존 장식을 보존한다. 자동 생성 재시도와 폰트 대체는 연결 AI가 판단하며, 가이드만으로 미적 판단을 인증하지 않는다. 앱의 일반 생성 도구도 생성 후보의 재판독과 보존을 수행한다. 여기서 '기본'은 앱에 새 자율 실행 큐를 추가한다는 뜻이 아니다.

## 완료 게이트

v2의 accepted 검수에는 전체 원본 영수증, 모든 저장 블록에 대한 고유 항목, 원본 영역·역할·처리 방식·복원 상태, 유효한 폰트 견본과 현재 작품 팔레트, 현재 렌더와 배치 검수, 생성 글자의 현재 독립 판독이 필요하다.

배경 복원과 한국어 문자 생성 이력은 `imageHistory.purpose`로 구분한다. 생성형 제거만 하고 문자까지 생성했다고 제출하거나 오래된 자산/폰트/팔레트/페이지의 영수증을 재사용하면 통과하지 못한다. 고립 음절 등 검수 경고에는 구체적인 예외 이유가 필요하며 overflow는 예외로 완료할 수 없다. 미해결 원문·오자·누락은 accepted로 올릴 수 없다.

폰트 대체는 검수 후 완료할 수 있으나 `accepted-with-font-substitutions`와 페이지·항목·사유 목록이 함께 반환된다. `needs-correction`/`blocked` 보고서와 기존 composite 상태는 연결 중단 후 진행 상황을 복구하는 데 사용한다.

서버가 확인하는 것은 증거의 존재·실제 바이트·최신 상태·계측이다. 원본에 없는 OCR 항목을 발견했는지, 견본을 미적으로 잘 비교했는지, 번역이 전문 역식 수준인지는 연결 AI의 시각·언어 판단이다. 또한 외부 AI의 자연어 '완료' 발언을 서버가 차단할 수는 없다. 서버의 정밀 완료 상태를 근거로 삼아야 한다.

## 검증과 경계

회귀 시험은 `mcpDetailedTranslationQuality`, `mcpGeneratedTouchup`, `mcpSoundEffectCandidates`, `mcpCorrectedGlyphReadback`, `mcpWorkTypographyPolicy`, `mcpQualityNativeContracts`와 기존 MCP/renderer 시험을 사용한다. 실제 Electron·OAuth HTTP의 네이티브 시험은 `.tmp/mcp-v2-native.cjs`, 결과는 `.tmp/mcp-v2-native-data/acceptance.json`이다. 원본 영수증, 일반/문맥 견본, 팔레트 CAS·중복 적용, 실제 후보 합성, 보정 횟수·중복 요청, 저장 페이지 보존을 확인했다. 이 시험은 생성 모델을 대신하지 않는다.

앱 Codex 재로그인 후 실제 생성 시험도 통과했다. 기존 설정의 GPT-6 Astra 이미지 컨트롤러와 GPT Image 백엔드에서 `쿠웅`을 1회 생성하고, 독립 재판독과 적용 후 합성 픽셀의 재판독이 모두 `쿠웅`으로 일치했다. 이어 공개 MCP lettering batch로 외곽선을 보정하고 재판독했으며, 원본 PNG SHA는 동일하고 합성 픽셀 SHA와 composition fingerprint는 달라졌다. Undo 뒤 블록 상태와 원본 파일의 바이트도 일치했다. 결과는 `.tmp/mcp-v2-real-generation/acceptance.json`, `touchup-acceptance.json`이다.

추가로 같은 실제 생성 자산의 받침 `ㅇ`을 공개 보정 명령으로 지운 통제 사례를 시험했다. 독립 판독은 `쿠우`를 반환하고 passed=false였다. 같은 영역을 restore한 실제 픽셀은 `쿠웅`, passed=true였다. 두 판독의 원본 PNG SHA는 같고 합성 픽셀 SHA는 달랐으며 두 번 Undo로 블록·원본 바이트가 복원됐다. 기록은 `jongseong-acceptance.json`, 이미지는 `jongseong-hide.png`, `jongseong-restore.png`다. 이는 보정 픽셀을 실제로 읽는 음성·양성 대조 시험이며, 자연 발생한 생성 오류를 AI가 자율적으로 미적 복구했다는 점수나 작품 전체 평가로 해석하지 않는다.

말줄임표 수정과 여러 후보 채택도 실제 자산으로 통합 검증했다. 첫 발효 영애 시험에서 탈락한 `쩌적…`, `쿠구궁…` PNG를 격리된 합성 시험 페이지에 후보로 보존하고, 공개 MCP의 `candidateIds`로 한 번에 적용했다. 실제 독립 판독은 각각 `쩌적...`, `쿠구궁...`를 반환했고 모두 passed=true였다. 이미지 생성 호출은 0회, PNG 바이트는 원래 후보와 동일하며 Undo/Redo의 저장 블록도 일치했다. 결과는 `.tmp/mcp-v2-real-candidate-salvage-02/acceptance.json`이다. 최초 시험 하네스의 Undo 비교에서는 JSON 저장으로 제거되는 `undefined` 속성을 입력 객체와 비교한 오류가 있었고, 저장 후 상태와 대조하도록 바로잡았다. 제품 저장 계약은 바꾸지 않았다.

실제 PageArtwork와 exporter의 픽셀 parity는 `.tmp/page-artwork-pixel-parity/51648-1791439258645/artifacts`에 보존했다. 일반/메타데이터 불일치 경로 모두 차이 0픽셀이고 PSD 알파·레이어도 확인했다. 넓은/좁은 화면 QA는 `C:/tmp/manga-mcp-v2-wide-03.png`, `C:/tmp/manga-mcp-v2-narrow-01.png`다. 임시 QA 엔트리는 제거했다. 캡처는 사용자 기존 저장 상태를 재현하며 개선 후 번역 평가가 아니다.

## 자모 부분 이동과 자형 검사 추가

사용자가 지적한 실제 `쾅`·`욱`은 OCR에서 문구를 맞힐 수 있지만 자모의 상대 위치가 어색한 사례다. 재판독 일치만으로는 이 문제를 차단할 수 없으므로, 정답 문구와 OCR 추측을 보여주지 않는 별도의 자형 검사를 추가했다. 자음·모음·받침·상대 배치의 네 판단과 구체적인 이유를 저장하고, 결함은 합성 crop의 0..1000 좌표로 반환한다. `inspectionGeometry`는 이를 원본 페이지 픽셀에 대응시키는 crop·페이지 크기·출력 크기다.

정밀 완료에는 version 2 자형 검사에서 모든 해당 항목이 valid이고 배치가 valid여야 한다. uncertain, 누락된 검사, 이전 version 1 검사, 미해결 결함은 OCR 일치 여부와 무관하게 통과하지 못한다. 외부 PNG와 직접 보정한 생성 이미지에도 현재 PageArtwork의 합성 픽셀을 검사한다. 검사 모델의 미적 판단을 객관적인 전문 품질 인증으로 표현하지 않는다.

v2 composite의 기존 policy fingerprint에도 `generatedGlyphShapeVersion: 2`를 결합한다. 업데이트 이전의 OCR 전용 완료 기록은 페이지 revision이 같아도 현재 완료 근거가 되지 않는다. 명시적 v1의 기존 fingerprint는 바꾸지 않는다. native source와 전체 화 완료 관련 14개 회귀 시험에서 이 호환 경계를 확인했다.

첫 실제 분리 검사에서는 `욱`만 차단하고 `쾅`은 놓쳤다. 이 실패를 `.tmp/mcp-v2-partmove-probe/before-receipts.json`에 보존했다. 이후 네 구성 요소와 위치를 명시적으로 점검하는 version 2에서는 두 이미지 모두 OCR가 문구를 맞혔지만 passed=false였다. `쾅`은 ㅋ이 ㅗ의 짧은 세로획보다 왼쪽에 놓이는 문제, `욱`은 길어진 ㅜ 옆으로 ㄱ이 밀리는 문제를 지적했다. `.tmp/mcp-v2-partmove-probe/before-receipts-v2.json`에 결과를 저장했다. 중간 재검사 하네스에서 편집 인계 응답을 구독하지 않아 10분 후 취소된 실행도 보존했으며, 응답을 연결한 뒤 실제 검사를 실행했다. 동일 결과를 통과할 때까지 재추첨한 것이 아니다. 별도 자율 보정 시험의 최초 검사에서도 두 결함이 다시 차단됐다.

편집기의 효과음 보정에 **부분 이동**을 추가했다. 자유 선택/사각 선택 후 안쪽을 끌어 이동하고, 방향키로 원본 페이지 기준 1px, Shift로 10px씩 조정한다. Enter/적용 버튼은 하나의 이력으로 저장하며 Escape/취소는 미리보기만 취소한다. 기존 칠하기·마스크·외곽선·변환과 함께 작동한다. 선택 조각의 이동이며 조각별 크기/회전 도구는 아니다. 전체 레이어의 기존 변환은 그대로 사용할 수 있다.

공개 계약은 기존 `generated-touchup.edits[].moves`다. 각 명령은 `space: asset | page`, `polygon`, `from`, `to`를 받는다. 명시한 좌표계의 0..1000 좌표이며, 페이지 좌표는 기존 회전·원근·왜곡의 역변환으로 자산 좌표에 대응시킨다. 저장된 `partMoves`는 자산 좌표의 polygon·offset과 앞선 paint/mask 개수를 기록한다. 한 명령 안에서는 이동을 먼저 하고 새 붓 보정을 뒤에 적용한다. 이동 순간의 합성 픽셀이 잘려 이동하며, 이후 복구 붓은 그 합성 상태 이후의 마스크를 복구한다. 이전 이동 자체는 Undo로 되돌린다. 최대 16회, 선택점 3~128개이며 캔버스 밖으로 잘리는 이동은 거부한다.

원본 PNG와 문구를 덮어쓰지 않고, 기존 이미지 SHA·페이지 revision·candidate revision·2회 후보 보정 예산·중복 요청·Undo/Redo를 재사용한다. retained candidate에도 같은 이동 입력을 사용할 수 있다. 수정된 픽셀은 새 재판독/자형 검사를 받아야 하며 이전 영수증을 재사용할 수 없다.

실제 native MCP의 페이지 좌표 이동·저장·중복 요청·Undo/Redo 시험은 `.tmp/mcp-v2-partmove-native/acceptance.json`에 있다. 15,298픽셀이 바뀌었고 대상 블록 밖 변경은 0픽셀이었다. 원본 PNG와 다른 블록은 동일했고 Undo/Redo의 전체 출력도 각각 이전/이후와 바이트가 일치했다. 이는 이동 기능 검증이며 해당 이동만으로 한글이 완성됐다는 품질 판정이 아니다.

## SOL 6.1 High 일반 번역·식자 시험 — 2026-10-09

사용자가 이미지 보정은 Astra와 SOL 모두 만족스럽지 않다며 평가에서 제외하도록 방향을 바꿨다. 앞의 보정 시험에서 서버 검수가 통과한 사실은 보존하지만, 그것이 사용자의 시각적 마감 기준을 만족했다는 뜻은 아니다. 실행 중이던 이미지 보정·전체 이미지 작업 시험을 중단하고 `trial-aborted.json`에 이유를 남겼다. 이후 생성 자모의 이동·붓질 성능을 더 튜닝하거나 성공 사례로 다시 선정하지 않았다.

실제 app-server의 모델 목록에서 `gpt-6.1-sol`과 `high` 지원을 확인했다. 첫 전체 작업 `sol61-whole-01`은 이미지 생성의 502 과부하와 모델 `serverOverloaded`로 실패했다. 이를 번역 실력의 실패나 완료된 품질 비교로 세지 않는다. 재시도 및 보정 시험도 원래 로그를 보존했고 사용자 지시에 따라 중단했다. 사용자 원본·보관함·출력 동기화는 모든 시험에서 분리했다.

새 `sol61-general-01`은 「잊힌 영애」 2.1화의 같은 원본 7장을 새 화로 가져왔다. 이전 Astra 시험 `whole-chapter-final-03`에서 복원 **배경만** 복사했고 번역문·블록·폰트·팔레트·생성 글자·배치는 전달하지 않았다. 원본 SHA와 배경 SHA를 고정했다. 사용자 프롬프트는 **“이 화 번역해줘. 이번에는 이미지 작업은 제외하고 번역과 식자만 해줘. 효과음도 번역문은 남겨줘.”**였다. 별도의 품질 지시나 도중 조언은 주지 않았다. 따라서 일반 번역·식자의 분리 시험이며, 단문 “번역해줘” 전체 이미지 경로의 재시험으로 표현하지 않는다. `source-manifest.json`의 최초 import 설명은 원본 입력만 기술하며, 실제 전체 입력 범위는 `trial-context.json`과 `background-manifest.json`을 함께 읽어야 한다.

MCP 호출은 123회이며 7회가 오류로 반환됐다. 넓은 빈 문단 경고, 실제 넘침, 항목별 reason 누락, correction 단계 계약, limit 상한, 실행 중 자식 작업, 복원 배경의 검수 상태에서 거절됐다. 모두 추가 사용자 지시 없이 수습했다. 원래 검수에서 backgroundRestoration을 `not-applicable`로 제출했지만, 저장된 복원 배경이 있으면 그 배경에 대한 최종 시각 검수는 필요하므로 완료가 거절됐다. 일반 대사는 대체로 의미와 이야기 흐름을 유지했고, 대사·독백·외침의 서체 역할도 유지했다. 그러나 「현자」의 `전진! / 전진하라!`, 「노미」의 `잠깐만요`처럼 한국어를 낱글자로 세운 배치가 남았다. 「노미」의 외모 질문, 일부 부연 대사와 주석은 여백에 비해 작았으며, `ばっ!!`→`두둥!!`, `にゅ…`→`덥썩…`의 효과음 어감과 같은 화자의 존댓말·반말 혼용도 후속 검토 대상이다. 이것은 생성 한글 획 보정의 문제가 아니라 번역·폰트 식자 판단의 차이다. 최종 수정에서 「노미」 첫 페이지의 고립된 물음표, 마지막 페이지의 `지팡이…?`와 `이렇게 쓰는 거야.`는 더 자연스럽게 묶였다.

FLUX 조합에서는 큰 효과음 주변의 일본어 획, 새로 생긴 빈 말풍선, 각진 독백 상자 테두리 소실이 남았다. 엔진 자체와 모델의 제거 영역 선택을 이 실험만으로 분리해 원인으로 확정하지 않는다. 「제국 우주군」 1페이지, 「금화」 1페이지는 제작 SOL이 최종 완료에서 제외했다. 「현자」는 3~5페이지의 복원 문제로 다섯 페이지 묶음을 보류했고 1~2페이지만 따로 승인하지 않았으므로 0/5가 다섯 장 모두의 번역 실패를 뜻하지 않는다. 「노미」는 1·4페이지 잔획과 4페이지 테두리 문제를 명시하고 미완료로 종료했다. 자동 이미지 보정 제외에 따라 「현자」의 paint 1회, 「노미」의 같은 원본 restore 요청 2회도 적용되지 않았다. 원래 restore 기능이 없거나 사용자가 두 번 거절한 사례로 해석하지 않는다.

별도 AI는 17/20장을 통상 독서 가능하다고 판단했지만, 「금화」의 새 빈 말풍선을 놓쳤고 「현자」 3페이지의 부자연스러운 흰 복원 영역도 결점으로 확정하지 않았다. 직접 확인 기록을 함께 남긴 이유다. 최종 native v2 완료는 8/20이며 이 역시 전문가 품질 점수가 아니다. 모든 페이지는 원본과 최종 결과를 직접 보았고, 먼저 본 checkpoint에서 변경된 최종본은 다시 확인했다. 20/20장의 실제 최종 렌더 픽셀이 수집 PNG와 일치했고 읽기 전용 계측으로 저장 화가 바뀌지 않았다. 실제 상자 overflow는 「현자」 2페이지 하단 `와아!` 한 곳이며, PNG에서 음절 자체가 잘린 것은 확인되지 않아 상자 넘침과 실제 잘림을 구분했다.

「노미」의 정식 검수 미완료에는 MCP 사용성 문제도 있었다. review-only plan에 `pageAttempts=0`을 넣은 뒤 실행 비용 부족으로 중단했는데, 기존 오류는 부족한 예산 항목이나 수량을 알려주지 않았다. 같은 혼동이 다른 작품에서도 반복됐으므로 네 제작 결과를 고정한 **후** `carrot_prepare_composite` 설명에 검수당 admission 1회와 선택 페이지당 pageAttempt 1회의 비용을 명시했다. 예산 오류에는 정확한 항목, 사용량, 이번 비용, 한도와 잔여량을 추가했다. 예산 계산·차감·완료 조건은 바꾸지 않는다. 5페이지 검수에 예산 0·4·5를 준 경우와 모델 예산·페이지별 편집 상한을 검사해, 거절 시 부분 차감이나 렌더 실행이 없고 충분한 기존 승인 범위에서만 실행되는지 확인했다. 관련 3개 파일의 테스트 19개가 통과했다. 네 작품의 점수와 완료 수는 안내 수정 전의 실제 기록이며 이 수정으로 SOL의 완료율이 개선됐다고 주장하지 않는다.

원본·결과·독립 검수·직접 확인 사항은 `.tmp/mcp-quality-v2-evaluation/sol-flux-review.html`에서 작품과 페이지를 바꿔 볼 수 있다. 집계는 `sol61-flux-four-results.json`, 작품별 근거는 각 root의 `acceptance.json`, `final-layout-inspection.json`, `trial-tool-failures.jsonl`, `source-preservation.json`과 `*-audit/assessment.json`이다. 사용자 원본 20장과 원본 화·작품 메타데이터, 이전 고정 manifest는 그대로 보존했다. 이번 표본으로 Astra 대비 우열, 사용자 수작업 초과 품질 또는 다른 장르 전체의 성능을 인증하지 않는다.

후속 안내 수정의 최종 `npm run check`는 **27개 gate, 10,474개 테스트 성공, 실패 0개, skip 9개**로 통과했다. 총 381.971초이며 타입·lint·architecture·coverage·build·PageArtwork/exporter 픽셀 parity·이미지 프로토콜·bundle 검사를 포함한다. `.tmp/mcp-sol-flux-check-01.stdout`, `mcp-sol-flux-check-01-tests.log`, `mcp-sol-flux-check-01-timings.json`에 결과를 보존했다. 네 제작 실행과 최종 빌드의 차이는 위 예산 오류와 composite 도구 설명 두 main 모듈 및 source map, 총 네 파일이다. renderer·shared·page-export는 동일하며 `sol61-flux-four-postcheck-code-delta.json`에 SHA를 기록했다. production renderer 변경은 없었다. 비교 HTML은 실제 브라우저에서 네 작품 선택과 이미지 로드를 확인했고 좁은 390px 창에서도 문서·이미지의 가로 넘침이 없었다.
